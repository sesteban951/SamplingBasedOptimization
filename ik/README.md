# IK Pipeline — Output Format

## `results/ik_fullrobot.csv`

Generated by `pipeline_srb_ik.py` after every successful run. Intended for downstream consumption (matches the `yaml_to_csv.py` `TARGET_JOINTS` convention from `traj_opt`).

### Columns (37 total)

| Index | Name | Description |
|-------|------|-------------|
| 0 | `time` | Timestamp (s) |
| 1 | `com_x` | CoM position x (m) |
| 2 | `com_y` | CoM position y (m) |
| 3 | `com_z` | CoM position z (m) |
| 4 | `quat_x` | Body quaternion x (pinocchio/xyzw convention) |
| 5 | `quat_y` | Body quaternion y |
| 6 | `quat_z` | Body quaternion z |
| 7 | `quat_w` | Body quaternion w |
| 8–19 | leg joints | 12 leg joints (IK-solved) |
| 20–22 | waist joints | `waist_yaw`, `waist_roll`, `waist_pitch` (zero) |
| 23–29 | left arm | shoulder + elbow + wrist (zero) |
| 30–36 | right arm | shoulder + elbow + wrist (zero) |

Full joint order (columns 8–36):
```
left_hip_pitch_joint, left_hip_roll_joint, left_hip_yaw_joint,
left_knee_joint, left_ankle_pitch_joint, left_ankle_roll_joint,
right_hip_pitch_joint, right_hip_roll_joint, right_hip_yaw_joint,
right_knee_joint, right_ankle_pitch_joint, right_ankle_roll_joint,
waist_yaw_joint, waist_roll_joint, waist_pitch_joint,
left_shoulder_pitch_joint, left_shoulder_roll_joint, left_shoulder_yaw_joint,
left_elbow_joint, left_wrist_roll_joint, left_wrist_pitch_joint, left_wrist_yaw_joint,
right_shoulder_pitch_joint, right_shoulder_roll_joint, right_shoulder_yaw_joint,
right_elbow_joint, right_wrist_roll_joint, right_wrist_pitch_joint, right_wrist_yaw_joint
```

### Loading

```python
import numpy as np

data = np.loadtxt("ik/results/ik_fullrobot.csv", delimiter=",", skiprows=1)
times  = data[:, 0]
com    = data[:, 1:4]   # xyz
quat   = data[:, 4:8]   # xyzw
joints = data[:, 8:]    # 29 joints
```

### Notes

- **Quaternion convention**: xyzw (pinocchio). MuJoCo uses wxyz — swap `[4:8]` → `[qw, qx, qy, qz]` if needed.
- **Unactuated joints** (waist, arms, wrists) are zero; the IK only solves the 12 leg joints.
- The joint→column mapping is built dynamically from the pinocchio URDF model at runtime.

## Other outputs in `results/`

| File | Description |
|------|-------------|
| `ik_q_pin.csv` | Raw pinocchio q (nq=36): `px,py,pz,qx,qy,qz,qw,joints×29` |
| `ik_q_mujoco.csv` | MuJoCo qpos (nq=36): `px,py,pz,qw,qx,qy,qz,joints×29` |
| `ik_time.csv` | Timestamps matching `ik_q_pin.csv` rows |
| `ik_fullrobot.csv` | Full-robot CSV described above |
| `workspace_boundary_2d.csv` | Raw IK bisection boundary: `x_com, pitch_rad, pz_min` |
| `workspace_poly_coeffs_2d.csv` | Degree-3 2D polynomial fit coefficients for `pz_min(x, pitch)` |
| `workspace_boundary.csv` | 1D envelope (worst-case over pitch): `x_com, pz_min` |
| `workspace_poly_coeffs.csv` | Degree-4 1D polynomial coefficients |
| `workspace_sagittal_2d.png` | Heatmap + slice plots of the 2D workspace surface |
| `workspace_sagittal.png` | 1D workspace boundary plot |

## Running the pipeline

```bash
# Full run (SRB solver + IK + visualize)
conda run -n env_sbo python ik/pipeline_srb_ik.py --config srb.config.smalljump

# Skip re-solving (reuse existing SRB results)
conda run -n env_sbo python ik/pipeline_srb_ik.py --config srb.config.smalljump --skip-solve

# Regenerate workspace boundary (run once, or after changing robot model)
conda run -n env_sbo python ik/squat_workspace.py
```
